# Balanced Experiment A - Preregistered Specification

Status: **proposed only; not implemented, authorized for release, or supported by outcome evidence**.

Ruleset ID: `balanced-experiment-v1`
Player-facing name: **Balanced Experiment A**

This document turns the current balance audit into falsifiable product hypotheses. It does not change or reinterpret Classic (`original`). Every number below is a proposed experiment threshold to test, not evidence that the threshold is fun, fair, or achievable.

## Isolation Contract

- Classic remains the default and keeps source-authentic data under `content/original` and TD-017.
- Balanced Experiment A must use a distinct ruleset ID, save namespace, score-board namespace, cohort ID, and visible persistent label.
- A Classic save cannot be silently migrated into or scored by this experiment. Import, if later approved, must be an explicit copy with a one-way warning.
- Hyper is disabled in the first experiment so time-economy effects are identifiable. A speed option requires its own preregistered cohort.
- No release claim may cite the controlled reachability trace or the historical P14V policy corpus as player evidence. Human evaluation uses schema v3 and a newly frozen experiment artifact.

## Required Measurement Outputs

Every experiment report must include, without dropping incomplete runs:

- before/after faucet, sink, productive-value, and conversion-loop tables;
- hull count versus score and seeded Space outcome curve;
- real-runtime weapon TTK, resource consumption, and late-game selection counts;
- controlled reachability milestones labelled as deterministic automation;
- policy-seed completions, classified stops, legal deaths, and bottlenecks;
- schema-v3 human foreground-active and wall milestone distributions, background/closed exposure, mode policy, completion, deaths, abandonment, and verbatim bottleneck wording.

## Promotion Decision

The first cohort is exploratory but preregistered. Meeting automated thresholds only makes the build eligible for human testing. Meeting the five-session measures is not population proof; it permits a product owner to choose a larger study, revise the experiment, or reject it. Promotion to a supported mode requires a dated decision, save-compatibility plan, accessibility pass, production gates, and a direct Classic-versus-experiment comparison. Until then, documentation and UI must say **proposed experiment**, never **balanced** as an established fact.
